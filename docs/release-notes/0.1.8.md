**Unsigned build.** No code-signing certificate exists. Verify files against `SHA256SUMS.txt` before running them.
Windows SmartScreen will warn about the MSI and the exe.

## What changed
- **Quick Setup is automated.** Missing Ollama, Codex CLI or Claude Code are installed for you with winget (per-user, no administrator rights). Each install first shows its own approval with the exact package, version, source and changes. A stopped Ollama is started with its own app.
- **Retry works.** The Install step detects again and re-plans every time, instead of repeating the plan from before.
- **Fix → Start runtime** on Stacks and Templates starts Ollama instead of telling you to.

## Honest status
- The automated pieces were each tested live on the build PC:
  - Catalogue installs of Codex 0.161.0 and Claude Code 2.1.302 (0.1.7 run).
  - Starting a stopped Ollama 0.40.6, which kept running after the app's process executor closed.
  - A full Quick Setup run in the installed app has **not** been clicked through end to end yet, because Codex and Claude Code are already installed on the build PC.
- Supported configurations are unchanged from 0.1.7: Codex + llama3.2 is Supported and Verified; Claude Code + llama3.2 failed validation (model too small).
- The updater is still OFF (no release signing key exists).

## Upgrading from 0.1.7
Install the MSI over 0.1.7 (major upgrade). Settings, stacks and projects are kept.
