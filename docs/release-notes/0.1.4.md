# DarkCipher AgentControl 0.1.4 — release notes (2026-10-19)

**Unsigned build.** No code-signing certificate exists. Verify files against `SHA256SUMS.txt` before running them.
Windows SmartScreen will warn about the MSI and the exe.

## What is in this folder

| File | What |
|---|---|
| `DarkCipherAgentControl-0.1.4-win-x64.msi` | Per-user installer (no admin rights). Installs to `%LOCALAPPDATA%\Programs\DarkCipher AgentControl`, plus Start-menu shortcuts (normal and Safe Mode). |
| `DarkCipherAgentControl-0.1.4-win-x64.zip` | Portable, self-contained app (no .NET install needed) |
| `DarkCipher.AgentControl.Sdk.1.0.0.nupkg` | Extension SDK (contracts only) |
| `dcx-ext-0.1.4-win-x64.zip` | Extension tooling (`new`, `validate`, `analyse`, `check-compat`, `pack`). Needs the .NET 8 runtime. |
| `samples/*.dcxext` | Two data-only and two code sample extensions |
| `DarkCipherAgentControl-0.1.4-docs.zip` | Full documentation |
| `sbom.cdx.json`, `THIRD-PARTY-LICENCES.txt` | CycloneDX 1.5 SBOM and licence list |
| `BUILD-INFO.txt` | Build date, SDK, test, self-test and validation results |
| `SHA256SUMS.txt` | SHA-256 of every file above (`sha256sum -c` format) |

## Changes since 0.1.3
- **New `tools\setup.ps1`**: one script that checks the build prerequisites and fetches the dependencies (the pinned .NET 8 SDK, the local WiX tool and all NuGet packages from the single official feed, using the locked restore). It only installs software (the .NET 8 SDK, through winget) when run with `-InstallMissing`. Git, Ollama and Claude Code are reported but never installed by the script.
- No application code changed. The app binaries behave as in 0.1.3.
- **Updates**: the in-app updater is still OFF and fails closed. Safe updates need a release signing key, and none exists; none was invented. Install a new release by running the new MSI (per-user, upgrades in place) after checking `SHA256SUMS.txt`.

Unchanged from 0.1.3; see `docs/REPORT.md` in the docs bundle.
